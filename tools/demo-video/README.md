# 소개 페이지 동작 영상 촬영·편집 정리

`web/public/assets/bootvolume-demo.mp4`(소개 페이지 맨 위 영상)를 어떻게 찍고 편집했는지 정리한 문서다. 두 번 만들었다.

| 판 | 날짜 | 촬영 도구 | 편집 도구 |
|---|---|---|---|
| 1판 | 2026-11-02 | `legacy-1102/run.sh` + `drive.swift` (손쉬운 사용으로 위치를 읽어 자동 조작) | `legacy-1102/compose.py` |
| 2판 | 2026-11-05 | `mouse.swift` (좌표를 직접 넣는 조작 도구) + ffmpeg 화면 녹화 | `compose.py` (1판 편집 도구를 그대로 쓰고 원본 시각만 바꿈) |

영상 규격은 두 판 모두 같다. **1920×1242, 30fps, 21.0초, H.264, 소리 없음**이다.

## 2. 화면과 좌표

### 2.1 화면 크기
- 이 Mac 의 화면 논리 크기는 **1710×1107pt**(배율 2)이고, 녹화 원본은 **3420×2214px** 이다.
- 확인 명령: `osascript -e 'tell application "Finder" to get bounds of window of desktop'` → `0, 0, 1710, 1107`
- 편집 도구의 `S=2.0` 은 pt → px 배율이고, `1710`·`1107` 이 화면 pt 크기다. 화면 크기가 바뀌면 이 셋을 고친다.

### 2.2 좌표 뽑는 법
2판은 좌표를 직접 넣었고, 다음 순서로 쟀다.

1. **메뉴 막대 아이콘**: 오른쪽 메뉴 막대만 캡처한다.
   ```sh
   screencapture -x -R 1100,0,610,34 bar.png     # x, y, 폭, 높이(pt)
   ```
   그림은 2배라서 **그림 속 px ÷ 2 + 1100** 이 화면 x(pt)다. 스피커 모양 아이콘이 BootVolume 이다(그림 x≈514 → 1357pt, y=17pt).
2. **패널 안 슬라이더**: 아이콘을 눌러 패널을 연 뒤 패널 영역을 캡처한다.
   ```sh
   screencapture -x -R 1010,0,700,520 panel.png
   ```
   **그림 px ÷ 2 + 1010** 이 화면 x 다. 부팅음 슬라이더 줄은 y=165pt.
3. **슬라이더 값 ↔ x 좌표**: 값 60 일 때 손잡이 x 와 80 일 때 x 를 캡처로 재서 1단위 폭을 구했다.
   - 60 = **1506pt**, 80 = **1533pt** (1단위 ≈ 1.35pt, 값은 5 단위로 끊긴다)
   - **1537 로 놓으면 85 가 된다.** 첫 촬영에서 이 때문에 85 로 찍혔다.
   - 저장이 끝난 뒤 `screencapture -x -R 1340,140,240,50 s.png` 로 값을 확인한다(숫자까지 보려면 폭을 넓힐 것).
4. **확인 사진은 직접 읽어 본다.** 아이콘 순서는 촬영 때마다 바뀔 수 있다(녹화 아이콘이 끼어들면 밀린다).

1판(`drive.swift`)은 좌표를 넣지 않고, 손쉬운 사용(AX)으로 BootVolume 의 메뉴 막대 항목(`AXExtrasMenuBar`)과 패널 안 슬라이더(`AXSlider`, 위에서 세 번째)의 위치·값을 읽어 계산했다. 손잡이 x = 슬라이더 왼쪽 + 8 + (값−5)/(100−5) × (폭 − 16).

## 3. 촬영 준비

| 할 일 | 방법 | 되돌리기 |
|---|---|---|
| 바탕화면 위젯 숨김 | `defaults write com.apple.WindowManager StandardHideWidgets -bool true; killall WindowManager` | 같은 명령에 `false` |
| 다른 앱 창 숨김 | 사용자가 미리 정리함(2판). 1판은 `apps.swift hide` 로 숨긴 앱 pid 를 적어 두고 `show` 로 되돌림 | |
| 터미널 창 치우기 | 터미널은 이 Mac 에서 숨겨지지 않는다. 창을 화면 밖으로 민다: `osascript -e 'tell application "Terminal" to set bounds of every window to {1800, 1200, 2600, 1700}'` → 실제로는 {1670, 1000, …} 로 끌려와 **오른쪽 아래 40×107pt 귀퉁이가 남는다**(편집에서 덮음, 5.4) | 미리 `get bounds of every window` 로 적어 두고 창마다 `set bounds of window N` |
| 메뉴 막대 앱 이름을 Finder 로 | `osascript -e 'tell application "Finder" to activate'` | |
| 음량 0 | `osascript -e 'set volume output volume 0'` | |
| 부팅음 60 으로 맞춰 두기 | 녹화 전에 패널을 열어 손잡이를 1506 으로 끌고 **5초 기다린 뒤** 닫는다 | 촬영 뒤 값은 80 |
| BootVolume 상태 | 패널에서 부팅음 켜기 ON, 도우미 '정상'인지 확인. 꺼져 있으면 '확인 필요 n' 이 영상에 나온다 | |

1판은 이 준비를 `run.sh` 가 자동으로 하고, 끝나면(`trap restore EXIT`) 위젯·숨긴 앱·밀어낸 창·커서 위치·부팅음 60 을 되돌렸다.

### 3.1 지뢰
1. **보라색 녹화 아이콘.** 화면 녹화를 시작하면 메뉴 막대에 보라색 아이콘이 생긴다. 녹화가 시작된 뒤에야 생기므로, 녹화를 켜 둔 채 기다려야 사용자가 옮길 수 있다. Cmd-드래그로 **BootVolume 아이콘보다 왼쪽**에 놓아야 BootVolume 아이콘 자리가 안 바뀐다. 오른쪽에 놓으면 아이콘이 밀려 클릭이 녹화 메뉴를 연다(2판 첫 촬영 실패 원인). 두 번째 녹화부터는 아이콘이 안 뜨기도 했다. 오른쪽 끝의 작은 보라색 점은 옮길 수 없고 영상에 남는다.
2. **BootVolume 아이콘이 막대 밖으로 빠지면 앱이 꺼진다.** Cmd-드래그 중 BootVolume 아이콘을 막대 밖으로 끌면 앱이 종료되고 `top.oodot.bootvolume` 설정에 `NSStatusItem VisibleCC Item-0 = 0` 이 남아 다시 켜도 안 보인다. 해결:
   ```sh
   defaults delete top.oodot.bootvolume "NSStatusItem VisibleCC Item-0"
   open -g /Applications/BootVolume.app
   ```
3. **부팅음 저장은 4~5초 걸린다.** 손잡이를 놓으면 슬라이더가 흐려지고(소리 없이 재는 중) 4~5초 뒤 밝아진다. 그 전에 마우스를 움직이면 안 된다. 2판은 놓은 뒤 **7초** 기다렸다.
4. **배경은 실시간 렌더**라 몇 초 사이에도 밝기가 조금씩 바뀐다. 미리 찍어 둔 배경 조각으로 덮으면 네모가 보인다.
5. zsh 에서 `"$DL[ap]"` 처럼 변수 바로 뒤에 `[` 가 오면 배열 첨자로 읽혀 빈 문자열이 된다. ffmpeg 필터 문자열엔 `${DL}[ap]` 로 쓴다.

## 4. 촬영

### 4.1 2판(11-05) 촬영 순서
녹화는 백그라운드로 켜 두고, 사용자가 녹화 아이콘을 옮기면("됐어") 조작을 시작했다.

```sh
# 녹화(화면 0번, 커서 포함, 30fps). 끝낼 땐 pkill -INT 로 보내야 파일이 닫힌다
ffmpeg -v error -y -f avfoundation -capture_cursor 1 -framerate 30 -pixel_format nv12 \
  -i "4:none" -c:v h264_videotoolbox -b:v 40M take4.mov </dev/null &
```
`4` 는 `ffmpeg -f avfoundation -list_devices true -i ""` 의 `Capture screen 0` 번호다.

조작(`mouse.swift` 를 `swiftc -O mouse.swift -o mouse` 로 빌드):
```sh
./mouse move 855 600 0.2 wait 2.5 \
        move 1357 17 1.0 wait 0.4 click wait 1.6 \
        move 1506 165 0.9 wait 0.4 drag 1533 165 1.4 wait 7.0
./mouse move 1300 420 0.8 wait 0.8 move 1357 17 0.7 wait 0.3 click wait 1.0 \
        move 900 640 0.8 wait 3.5 voldown wait 3.5
pkill -INT -f take4.mov
```

`mouse.swift` 명령:
| 명령 | 동작 |
|---|---|
| `move x y 초` | 현재 위치에서 (x, y) 로 이동. **60Hz**(16.7ms 간격), 곡선은 easeInOutQuad(`t<0.5 ? 2t² : 1−(−2t+2)²/2`) |
| `click` | 누름 → 80ms → 뗌 |
| `drag x y 초` | 누름 → 150ms → 같은 곡선으로 끌기 → 150ms → 뗌 |
| `voldown` | 음량 내리기 키(NX_KEYTYPE_SOUND_DOWN=1, systemDefined subtype 8, 누름 0xa00/뗌 0xb00, 50ms 간격). 음량이 이미 0 이라 소리 없이 음량 표시만 뜬다 |
| `wait 초` | 쉬기 |

### 4.3 1판(11-02) 촬영
`legacy-1102/run.sh <번호>` 한 번이 녹화 1회다.
1. 커서 위치·보이는 앱 목록을 적어 둠
2. 위젯 숨김, `apps hide`(일반 앱 전부 숨김, pid 기록), 0.8초 뒤 `wins_left` 로 남은 창(0층, 폭 50 이상, Dock·Finder·BootVolume 등 제외)의 pid 를 찾아 `park park` 으로 창을 (5000, 5000) 으로 밀어냄(원래 위치 기록). 그래도 남는 창이 있으면 녹화 중단

5. `drive demo`:
   - 1.5초 대기
   - 아이콘 가운데로 **1.1초** 이동, 0.3초, 클릭, 1.2초
   - 손잡이로 0.8초 이동, 0.3초, 누름, 0.12초, 80 까지 **1.6초** 끌기, 0.2초, 뗌

## 5. 편집

### 5.1 편집 도구 `compose.py`
1판 도구를 그대로 쓰고, 2판에서는 입력 파일(`take4.mov`)·원본 시각(`SEG`)·귀퉁이 덮기만 바꿨다. 확대 일정(`CAM`), 곡선, 부팅 장면, 인코딩은 1판과 같다.

실행(Pillow 필요):
```sh
swift make_applelogo.swift <작업폴더>/applelogo.png
python3 compose.py <작업폴더> <출력.mp4>    # 작업폴더에 take4.mov, applelogo.png
```
21초 630프레임에 약 26초 걸린다.

처리 흐름:
1. ffmpeg 로 원본을 30fps RGB 로 풀어 순서대로 읽는다(`scale=out_range=full,format=rgb24`)
2. 출력 프레임마다 `SEG` 로 원본 시각을 정하고 그 프레임을 가져온다
3. 귀퉁이 덮기(5.4)
4. `CAM` 으로 배율·위치를 정해 `Image.resize((1920,1242), LANCZOS, box=…)` 로 잘라 줄인다
5. 부팅 구간은 직접 그린다(5.5)
6. ffmpeg 로 인코딩: `libx264 -preset slow -crf 21 -pix_fmt yuv420p -color_range tv -colorspace bt709 -color_primaries bt709 -color_trc bt709 -movflags +faststart`

### 5.2 시간 배치 `SEG` (출력 시작, 출력 끝, 종류, 원본 시작, 원본 끝)
출력 시각은 두 판이 같고, 원본 시각만 그 촬영본의 같은 장면에 맞춘다.

| 출력 | 1판(take7) 원본 | 2판(take4) 원본 | 원본 속도 |
|---|---|---|---|
| 0.0 – 8.0 | 11.2 – 19.2 | 24.2 – 32.2 | 1배 |
| 8.0 – 9.4 | 19.2 – 24.0 | 32.2 – 38.9 | 1판 3.4배 · 2판 4.8배(저장 대기를 줄임) |
| 9.4 – 10.6 | 24.0 – 25.2 | 38.9 – 40.1 | 1배 |
| 10.6 – 12.4 | 25.2 고정 | 40.1 고정 | 멈춤 |
| 12.4 – 17.4 | 부팅 장면 | 부팅 장면 | |
| 17.4 – 21.0 | 26.9 – 30.5 | 47.8 – 51.4 | 1배 |

2판 원본 시각을 고른 기준:
- 패널 열림 원본 27.75 를 출력 3.55 에 맞춤 → 첫 구간은 원본 = 출력 + 24.2
- 저장이 끝나는 37.5 와 커서가 비키기 시작하는 39.4 가 출력 9.4 – 10.6 안에 들어오게 둘째 구간 끝을 38.9 로
- 음량 표시 48.5 를 출력 18.1(1판과 같은 시각)에 맞춤 → 원본 = 출력 + 30.4

새로 찍으면 4.2 처럼 장면 시각을 재고 이 기준대로 `SEG` 의 원본 숫자만 바꾼다.

### 5.3 확대/축소 `CAM`
키 = (출력 시각, (배율, 화면 중심 x pt, 중심 y pt)):
```python
WIDE=(1.0,855,553.5); PANEL=(2.2,1320,252); HUD=(1.8,1300,308)
CAM=[(0.0,WIDE),(1.4,WIDE),(2.5,PANEL),(10.4,PANEL),(11.4,WIDE),
     (17.6,WIDE),(18.2,HUD),(19.4,HUD),(20.1,WIDE)]
```
- **곡선**: `cubic-bezier(.65,0,.35,1)`(앞뒤가 느리고 가운데가 빠름). x 에 대해 이분법 40회로 t 를 찾아 y 를 쓴다.
- **보간**: 키마다 (배율 s, 보이는 영역 왼쪽 위 tx, ty) 로 바꾸고(`tf`), 셋을 같은 곡선으로 **선형** 보간한다. CSS 의 `transform-origin: 0 0; translate(tx) scale(s)` 와 같은 방식이다.
- **화면 밖 방지**: 중심을 보이는 영역 반폭 안으로 자른다. 그래서 PANEL·HUD 는 사실상 **오른쪽 위 모서리 기준** 확대가 된다(오른쪽 끝·위쪽 끝이 화면 끝에 붙음).
- **걸리는 시간**: 확대 1.1초(1.4→2.5), 축소 1.0초(10.4→11.4), 음량 표시 확대 0.6초(17.6→18.2), 축소 0.7초(19.4→20.1).
- 영상 측정값(`measurements/`)으로 보면 배율이 눈에 띄게 변하는 구간은 확대 1.47 – 2.47초, 축소 10.47 – 11.37초, 17.67 – 18.17초, 19.5 – 20.07초다(곡선 양 끝이 아주 느려서 실제 움직임이 짧아 보인다).

### 5.4 터미널 귀퉁이 덮기
화면 밖으로 민 터미널 창이 오른쪽 아래(원본 px x ≥ 3340, y ≥ 2000)에 남는다. 원본 프레임마다:
- 바로 왼쪽 **(3160, 1920) – (3290, 2214)** 를 잘라 **좌우로 뒤집어** **(3290, 1920)** 에 붙인다.
- 붙일 때 위쪽 60px 은 투명도를 0 → 1 로 섞는다(`min(255, 255·y/60)`). 위쪽 경계 선이 안 보이게 한다.

시도했다 버린 것:
- 미리 찍은 깨끗한 배경 조각 붙이기: 배경이 실시간이라 밝기가 달라 네모가 보임
- ffmpeg `delogo`: 화면 끝에 닿은 영역이라 터미널 색을 끌어와 줄무늬가 생김
- 위쪽 배경을 상하로 뒤집기: 아래로 갈수록 어두운 배경이라 띠가 밝게 보임

### 5.5 부팅 장면(출력 12.4 – 17.4, 5초)
녹화가 아니라 직접 그린다. `bt` = 부팅 장면 안 시각(0 – 5).

| 0 – 0.5 | 직전 출력 프레임(10.6 – 12.4 에서 멈춘 화면) → 검정으로 섞기 |
| 1.0 – 1.3 | 로고·막대 나타남 |
| 1.3 – 3.8 | 진행 막대 0 → 100% |
| 3.8 – 4.1 | 로고·막대 사라짐 |
| 4.3 – 5.0 | 검정 → 로그인 장면 첫 프레임(이미 확대 계산된 것)으로 섞기 |

- 로고: SF Symbols `apple.logo`, 200pt, 흰색 0.96(`make_applelogo.swift`) → 알파 영역으로 자르고 **높이 96px** 로 줄임. 가로 가운데, 세로는 화면 가운데에서 **40px 위**.

### 5.6 포스터·정지 그림

### 5.7 확인 방법
- 모음 사진: `ffmpeg -i out.mp4 -vf "fps=2,scale=300:-1,drawtext=text='%{pts\:hms}':x=4:y=4:fontsize=16:fontcolor=yellow,tile=7x6" -frames:v 1 sheet.jpg`
- 1판과 나란히: `-filter_complex "[0]scale=240:-2[a];[1]scale=240:-2[b];[a][b]hstack,fps=2,…,tile=6x7"`
- 검은 구간: `ffmpeg -i out.mp4 -vf "blackdetect=d=0.1:pix_th=0.12" -an -f null -`
- 사이트 반영 확인: `curl -s https://bootvolume.oodot.top/assets/bootvolume-demo.mp4 | shasum` 와 로컬 파일 `shasum` 이 같은지

## 6. 2판을 만들며 있었던 일(11-05)

1. **처음엔 1판 편집을 눈으로 보고 따라 만들었다.** 1판 편집 도구가 세션 임시 폴더에 있다가 지워졌기 때문이다. ffmpeg `zoompan` 으로 확대 2.2배를 smoothstep 곡선으로 1.6 – 2.2초에 걸쳐 키우고, 9.9 – 10.5초에 줄였다. 부팅 장면은 1판 영상의 12.8 – 16.6초를 잘라 붙였다. 이 판을 한 번 배포했다(커밋 `01101e3`).
2. 사용자가 **"저번과 완전히 똑같게"** 를 요구해, 1판 영상을 프레임마다 재서 값을 뽑았다(`measure_zoom.py`).
   - 1판 영상을 회색조 PNG 630장으로 풀고(`ffmpeg -vf format=gray %03d.png`), 확대 안 된 프레임을 기준으로 삼아 각 프레임이 기준의 어느 부분을 몇 배로 키운 것인지 찾는다.
   - 320px 폭으로 줄여 비교(평균 절대차). 배율 1.0 – 2.45 를 0.02 간격 → 찾은 값 근처 0.002 간격. 기준점은 25가지(가로·세로 0, 0.25 … 1)를 해 보고 **오른쪽 위(ax=1, ay=0)** 로 확인.
   - 밝기 평균으로 페이드 시각을 잼: 사라짐 **12.40 → 12.90**(선형), 밝아짐 **16.70 → 17.40**(선형).
   - 장면 시각: 패널 열림 3.55, 끌기 6.7 – 7.55, 흐림 8.05 – 9.3, 저장 끝 9.55, 커서 비킴 10.05, 음량 표시 18.1.
   - 측정값은 `measurements/` 에 있다(시각, z=배율, ax/ay=기준점, err=차이).
3. 이어서 사용자가 **"저번 도구를 복원 못 하냐"** 고 물었다. 1판 작업의 Claude Code 대화 기록(jsonl)에 도구를 만든 명령과 고친 명령이 순서대로 남아 있었다. 그 명령들 가운데 파일을 만들고 고치는 부분만 같은 순서로 다시 돌려 최종판을 되살렸다.
   - `compose.py`: 작성 → `SEG` 마지막 구간 26.4→26.9 수정 → HUD 키 수정 → 카메라를 cubic-bezier 방식으로 교체 → ICON 키 삭제(`CAM` 최종). 되살린 판의 값은 2번 측정과 맞았다(오른쪽 위 기준, 2.2배·1.8배, 페이드 0.5초·0.7초).
   - `run.sh`·`drive.swift`·`apps.swift`·`wins_left.swift`·`park.swift` 도 같은 방법으로 되살렸고 Swift 4개는 컴파일을 통과했다.
4. 되살린 `compose.py` 에 2판 촬영본을 넣고 `SEG` 원본 숫자와 귀퉁이 덮기만 바꿔 다시 뽑았다.
